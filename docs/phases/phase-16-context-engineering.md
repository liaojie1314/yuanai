# Phase 16 - 人格文件、上下文压缩、钩子与外置记忆

- **前置条件**：Phase 7 记忆 / 知识库 / Skills / 人格控制面已交付并有真实运行证据
- **建议分支**：`feat/phase-16-context-engineering`
- **执行范围**：`soul.md` 人格文件、上下文压缩机制、Agent 生命周期钩子、外置记忆后端
- **阶段定位**：把「助理带进模型的那段上下文」从隐式拼接变成**可读、可审计、可裁剪、可携带**的工程对象

---

## 1. 产品目标

1. 人格有一份用户能整体读写、diff、版本化、导出的**正文文件**（`soul.md`），而不只是一堆表单字段
2. 上下文超预算时有明确的**压缩动作**（淘汰 / 摘要 / 外置），而不是只能截断尾部
3. 用户和插件能在 Agent 生命周期的固定点挂**钩子**，不必改后端代码
4. 记忆正文可以放在用户自己选择的后端（外置记忆），云端只保留检索所需的索引

### 1.1 非目标

- 不把 `soul.md` 变成可执行配置：它是人格正文，不承载工具授权、预算或路由规则
- 人格文件**不得放宽任何安全边界**（沿用 [Phase 7](./phase-7-memory-skills-automation.md) §8.5.2）
- 钩子不执行任意 Shell / 浏览器动作；需要这类能力时走 Phase 6 工具与执行节点
- 压缩不做「无损压缩」承诺：摘要必然丢信息，因此必须可追溯回原文
- 不在本阶段做跨用户共享人格模板或人格市场（见 [Phase 12](./phase-12-open-ecosystem.md) §5）
- 外置记忆不支持「把记忆托管给第三方 AI 服务再由其代为检索」——检索排序必须留在本系统内

## 2. `soul.md` — 人格文件

### 2.1 为什么需要文件形态

Phase 7 §3.6 已有人格模型、§8.5 已有人格编辑器与版本历史，但人格只以**结构化字段**存在。
由此产生三个现实问题：

- 用户无法一眼读完「这个助理到底是谁」，只能逐个字段翻
- 两个版本之间的差异只能按字段比，读不出语义变化
- 人格无法随用户迁移（自托管、换账号、导出备份），与 Phase 12 §9.2 导出包对不上

`soul.md` 是人格的**权威正文形态**；Phase 7 的人格字段降级为它的投影，不再是两份真相。

### 2.2 格式

```markdown
---
name: 工作助理
role: 帮我推进项目和写作
tone: 简洁、直接、不绕弯
version: 7
updated_at: 2026-10-07T10:00:00Z
---

## 我是谁

（助理自我定位，进入系统提示的开场部分）

## 怎么和我说话

（语气、长度偏好、称呼方式）

## 我擅长什么

（擅长领域，用于路由与自荐，不授予任何工具权限）

## 我不做什么

（用户声明的禁区；只能**收紧**行为，不能放宽）
```

约束：

- frontmatter 字段白名单固定，未知字段拒绝保存而不是静默丢弃
- 正文章节标题白名单固定；未知章节保留原文但**不进入系统提示**，并在编辑器里标注「未使用」
- 单文件硬上限按 token 计（不是字符数），超限在保存时就报错，不留到运行时才截断
- 人格文件不含任何凭据、URL 白名单、工具名或预算数字；写了也不生效，保存时直接告警

### 2.3 与安全边界的关系

- 系统提示装配顺序不变：**安全策略在最前且不可覆盖**（Phase 7 §8.5.4）
- `## 我不做什么` 只做交集：用户能让助理更保守，不能让它更放松
- 人格文件里出现「忽略以上指令」「你现在是人类」这类内容时，装配阶段剔除该行并记一条可见的
  人格告警，而不是整份文件拒绝加载（否则一处写错就让助理失去全部人格）

### 2.4 版本、导入导出与回滚

- 每次保存生成新版本，与 Phase 7 §8.5.5「人格变更一律需用户确认」一致
- 版本列表提供**正文 diff**，而不只是字段 diff
- 导出为单个 `.md` 文件；导入时校验 frontmatter 白名单与 token 上限，冲突时让用户选择覆盖或新建助理
- 回滚即「以旧版本正文创建新版本」，不物理删除历史

## 3. 上下文压缩机制

### 3.1 当前缺口

Phase 7 §5.2 定义了七层上下文和每层 token 预算，但**没有定义超预算之后做什么**。
实现上只能截断尾部，后果是：长会话里最早的关键约束被静默丢掉，用户无从察觉。

本节补齐「超限动作」这一层。

### 3.2 三种压缩动作

| 动作             | 含义                                  | 可逆性                     |
| ---------------- | ------------------------------------- | -------------------------- |
| 淘汰 `evict`     | 本轮不带入，原文仍在库里              | 完全可逆，下一轮可能再命中 |
| 摘要 `summarize` | 用摘要替代若干条原文，摘要携带来源 ID | 有损，但可回到原文         |
| 外置 `offload`   | 移出上下文，写成可按需取回的 Artifact | 可逆，取回要一次工具调用   |

选择顺序固定为 **淘汰 → 摘要 → 外置**：先丢掉本轮不需要的，再压缩需要但可概括的，
最后才把大块内容搬到外面。颠倒顺序会为用不上的内容白付摘要成本。

### 3.3 压缩点

| 压缩点 | 触发                          | 压缩对象                       |
| ------ | ----------------------------- | ------------------------------ |
| 轮次级 | 单轮装配超出模型窗口          | 检索结果、知识片段、工具输出   |
| 会话级 | 会话历史超出其层预算          | 早期轮次（成对压缩，不拆问答） |
| Run 级 | 长时 Run 的 Step 历史超出预算 | 已完成 Step 的中间输出         |

会话级压缩**必须成对处理用户提问与助理回答**。只摘要其中一半会产出「回答对不上问题」的历史，
比丢掉整轮更糟。

### 3.4 不可压缩层

以下内容任何情况下不参与压缩，预算不足时应**降级模型选择或拒绝执行并说明**，而不是压掉它们：

1. 平台安全策略
2. `soul.md` 的 `## 我不做什么`
3. 用户在当前任务中显式给出的约束
4. 当前待审批动作的完整描述与影响面

### 3.5 保真要求

- 每条摘要记录 `source_ids`，UI 上可展开到原文
- 摘要由模型生成时走 `ai_service`，与其他 AI 调用同一出口
- 摘要**不写入记忆**：它是上下文工件，不是用户事实。混进记忆会让摘要误差沉淀为长期记忆
- 用户可在会话里看到「此处已压缩 N 轮」的显式标记，不做无声压缩

### 3.6 预算与可观测

- 每次装配输出一条上下文装配记录：各层实际 token、触发的压缩动作、被压缩对象数量
- 压缩本身的成本计入 Run 成本，否则「省了上下文、多花了钱」无法被发现
- 指标：压缩触发率、压缩后窗口占用率、摘要 token 成本占比、取回外置内容的次数

## 4. 钩子 Hook

### 4.1 定义与边界

钩子是在 Agent 生命周期固定点运行的**声明式回调**。它能观察、能否决、能改写受限字段，
不能执行任意代码。

| 钩子点                 | 时机                     | 允许的动作                        |
| ---------------------- | ------------------------ | --------------------------------- |
| `on_run_start`         | Run 创建后、Planner 前   | 注入额外约束、拒绝启动            |
| `on_context_assembled` | 上下文装配完成、调模型前 | 读取装配记录、追加约束文本        |
| `on_tool_call`         | 工具调用前               | 拒绝、要求人工审批、改写参数      |
| `on_tool_result`       | 工具返回后               | 标记结果不可信、要求重试          |
| `on_step_end`          | 每个 Step 结束           | 记录、提前结束 Run                |
| `on_run_end`           | Run 终态                 | 通知、写 Journal、触发自动化      |
| `on_memory_candidate`  | 记忆候选生成后           | 拒绝入库、改写范围（用户级/私有） |

### 4.2 执行模型

- 钩子**同步执行**且有硬超时；超时按注册时声明的 `on_timeout` 处理
- `on_tool_call` / `on_memory_candidate` 这类有否决权的钩子**fail-closed**：超时或报错即拒绝该动作
- 纯观察类钩子（`on_step_end`、`on_run_end`）**fail-open**：失败只记日志，不拖垮 Run
- 同一钩子点多个钩子按注册顺序串行；任一否决即终止该点的后续钩子
- 钩子不得递归触发 Agent Run；需要这种编排时走 [Phase 17](./phase-17-multi-agent-collaboration.md)

### 4.3 安全

- 钩子看不到任何凭据：参数里的 secret 引用保持为引用，不解引用
- 钩子**不能提权**：不能把工具风险等级调低、不能跳过审批、不能扩大 delegation contract
- 用户自建钩子只能作用于自己的助理；插件钩子的作用范围由 Phase 12 Extension Manifest 声明
- 每次钩子执行写一条可观测记录（钩子 ID、耗时、决策），审计时能回答「这步为什么被拒」

### 4.4 与 Plugin SDK 的关系

Phase 12 §4 Plugin SDK 负责**插件如何打包与分发**；本节负责**钩子点与执行语义**。
插件注册钩子时使用本节定义的钩子点，不自定义新钩子点。

## 5. 外置记忆

### 5.1 当前缺口

Phase 7 §5.3 已有 `storage_location=local_node`：记忆正文留在桌面节点，云端只存索引元数据。
这是外置记忆的**一个特例**。缺的是通用形态：用户希望正文落在自己的对象存储、
自己的文件目录或自己的数据库里。

### 5.2 后端类型

| 后端             | 正文位置             | 检索方式                       | 离线行为               |
| ---------------- | -------------------- | ------------------------------ | ---------------------- |
| `cloud`（默认）  | 本系统数据库         | 云端 pgvector + FTS            | —                      |
| `local_node`     | 桌面执行节点         | 路由到在线节点（Phase 7 §5.3） | 明确不可用，不静默降级 |
| `user_object`    | 用户自有 S3 兼容存储 | 云端索引 + 取正文时按需拉取    | 明确不可用             |
| `user_directory` | 用户机器上的目录     | 经执行节点扫描并上报索引       | 明确不可用             |

### 5.3 索引与正文分离

- 云端**只保留**：嵌入向量、关键词索引、范围/类型/时间等元数据、后端定位符
- 云端**不得保留**：正文、`source_excerpt`、`structured_data` 等自由文本字段
- 命中后先把定位符交给对应后端取正文，再进入上下文装配
- 取不到正文时命中项降级为「有一条记忆但当前不可读」，不伪装成「没有这条记忆」

### 5.4 一致性与所有权

- 外置后端是**正文的真相源**；用户在后端直接删除文件后，下一次取回失败即把索引标记为孤立并提示清理
- 不做双写：不在云端留「以防万一」的副本，否则外置承诺不成立
- 切换后端是显式迁移操作，带进度与失败清单，不在后台悄悄搬

## 6. 数据模型增量

- `assistant_souls` / `assistant_soul_versions`：`soul.md` 正文、frontmatter 解析结果、token 计数
- `context_assemblies`：每次装配的分层 token、压缩动作、模型与 Run 关联
- `context_summaries`：摘要正文、`source_ids`、覆盖的轮次范围
- `hooks` / `hook_executions`：注册信息（作用域、钩子点、超时、失败策略）与每次执行记录
- `memory_backends`：用户配置的外置后端（类型、定位规则、健康状态），凭据走 SecretStore 引用
- `memories` 增列：`backend_id`、`locator`

Phase 7 的人格字段改为从 `assistant_souls` 投影，迁移时按现有字段生成首个 `soul.md` 版本，
保证存量助理不因本阶段丢失人格。

## 7. API

| 方法与路径                            | 说明                                |
| ------------------------------------- | ----------------------------------- |
| `GET/PUT /assistants/{id}/soul`       | 读写 `soul.md` 正文                 |
| `GET /assistants/{id}/soul/versions`  | 版本列表与正文 diff                 |
| `POST /assistants/{id}/soul/rollback` | 以旧版本正文创建新版本              |
| `GET /runs/{id}/context-assemblies`   | 上下文装配记录（分层 token 与压缩） |
| `GET /context-summaries/{id}`         | 摘要正文与来源原文定位              |
| `GET/POST/DELETE /hooks`              | 钩子注册管理                        |
| `GET /hooks/{id}/executions`          | 钩子执行审计                        |
| `GET/POST/DELETE /memory-backends`    | 外置记忆后端配置                    |
| `POST /memory-backends/{id}/migrate`  | 记忆正文迁移到该后端                |

新增/变更接口同步更新 `packages/types`。

## 8. 用户体验

- **人格页**：Markdown 编辑器 + 右侧实时预览「同一句话在当前人格下的回答」；未使用的章节与被剔除的
  越权行以警示条标出，不静默吞掉
- **上下文面板**：Run 详情里一屏看懂「这次带了什么进去」——分层占比、哪些被压缩、点开看原文
- **会话内标记**：被压缩的历史位置显示「已压缩 N 轮，点击查看」
- **钩子页**：按钩子点分组列出，显示最近决策与否决次数；fail-closed 的钩子醒目标注
- **外置记忆**：后端列表带健康状态；离线时记忆中心对应条目显示「正文暂不可读」而非消失

## 9. 测试要求

- `soul.md` frontmatter 未知字段被拒绝保存；未知章节保留但不进系统提示
- 人格正文中的提权语句被装配阶段剔除，且其余人格内容仍然生效
- 超 token 上限的人格文件在保存时失败，不留到运行时截断
- 压缩顺序为淘汰 → 摘要 → 外置，有用例断言该顺序
- 会话级压缩成对处理问答，不出现单边摘要
- §3.4 四类不可压缩内容在极端预算下仍完整进入上下文
- 摘要携带可解析的 `source_ids` 且能定位到原文
- 摘要不进入记忆候选
- `on_tool_call` 钩子超时按 fail-closed 拒绝该次工具调用；`on_run_end` 钩子失败不影响 Run 终态
- 钩子无法降低工具风险等级、跳过审批或扩大 delegation contract（逐条用例）
- 钩子参数中的凭据引用未被解引用
- 外置后端离线时命中项显示为「不可读」，不被当作「不存在」
- 云端不存在外置记忆的任何正文字段（schema 层与写入层各一条用例）
- 存量助理迁移后人格不丢失，首个 `soul.md` 版本内容与原字段等价

## 10. 验收标准

- [ ] 用户能完整读写一份 `soul.md`，并在版本历史里看正文 diff、一键回滚
- [ ] 人格文件导出后在另一账号导入，助理表现可复现
- [ ] 人格文件无法放宽安全或授权边界，有针对性用例
- [ ] 长会话触发压缩后，用户能看到压缩标记并回到原文
- [ ] 不可压缩内容在最紧预算下仍然完整
- [ ] 压缩成本计入 Run 成本并在 Run 详情可见
- [ ] 至少一个否决类钩子与一个观察类钩子在真实 Run 中生效，审计记录完整
- [ ] 钩子失败时的行为与注册声明一致（fail-closed / fail-open 各有证据）
- [ ] 记忆正文可迁移到一个外置后端，云端确认无正文残留
- [ ] 外置后端离线时系统明确报不可读，不静默少带记忆

**进入下一阶段的许可证**：上下文装配可解释、可审计、可裁剪；人格可携带且不提权；
钩子的否决权有边界且有记录；外置记忆的隐私承诺有 schema 级证据。
