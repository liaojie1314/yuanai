# Phase 9 - 生活、学习、工作空间与高价值连接器

- **前置条件**：Phase 8 安全治理、预算、租户隔离、审计和 kill switch 通过
- **建议分支**：`feat/phase-9-life-work-connectors`
- **执行范围**：全端产品体验、Connector 平台、场景模板、通知和后台治理
- **阶段定位**：将通用 Agent 内核转化为普通用户每天都能使用的生活与工作助理；OPC 作为专业工作模式之一

---

## 1. 产品原则

### 1.1 一个助理，多种生活空间

用户不应该先理解 Tool、MCP、Run 或 Workflow。产品以“空间”和“目标”组织：

- 个人生活：日程、家庭、旅行、购物、健康资料和日常事务
- 学习研究：课程、论文、笔记、语言学习和长期学习计划
- 职业工作：邮件、会议、项目、文档、数据和团队协作
- 创作者：选题、研究、内容生产、素材和发布计划
- 开发者：代码、GitHub、技术研究、部署和问题跟踪
- OPC/自由职业：客户、销售、内容、交付、财务资料和经营复盘

空间决定默认记忆、知识、连接、Skills、预算和审批策略，避免生活数据与工作数据无边界混用。

### 1.2 目标优先，不做 App 图标集合

用户表达“帮我准备明天的会议”，系统自行选择日历、邮件、知识库和文档工具。连接器页面用于授权与治理，不应成为主导航。

### 1.3 先产出草稿，再代表用户行动

首版默认策略：

- 研究、整理、分析、计划和生成草稿可自动执行
- 发信、发消息、创建共享事件、提交代码和公开发布需要审批
- 删除、付款、购买、账号安全设置保持人工或显式跳转

## 2. 信息架构

```text
主导航
├── 助理（对话 + Agent 任务）
├── 今天（提醒、待办、建议、等待审批）
├── 空间
│   ├── 生活
│   ├── 学习
│   ├── 工作
│   └── 自定义空间
├── 任务（目标、计划、运行和交付物）
├── 资料（知识库与 Artifact）
└── 自动化

设置
├── 连接
├── 记忆
├── Skills
├── 设备
└── 隐私与预算
```

### 2.1 “今天”页

不是新闻 Feed，而是行动中枢：

- 今天的日程、提醒和截止任务
- 正在运行、等待审批、等待本机设备和失败的 Agent Run
- 助理发现的少量高价值建议
- 自动化结果摘要
- 用户快速输入“今天还要做……”并转为目标/任务

主动建议每日默认不超过 3 条；用户忽略后降低同类建议频率。

## 3. Workspace 与任务模型

### 3.1 数据模型

- `workspaces`：类型、名称、图标、默认助理、隐私和预算
- `workspace_members`：个人空间仍只有所有者；为家庭/团队共享预留
- `goals`：期望结果、成功标准、时间范围和状态
- `tasks`：目标下的可执行工作，支持人工/Agent owner
- `task_dependencies`：前置关系，不自动形成无限 DAG
- `deliverables`：报告、文档、代码、图片、表格或外部链接
- `inbox_items`：待分类输入、外部事件和用户转发内容
- `external_objects`：第三方对象与 yuanai 对象的稳定映射

### 3.2 状态

- Goal：`draft / active / paused / achieved / abandoned`
- Task：`inbox / planned / ready / running / waiting / review / done / cancelled`

Agent 可以建议拆分任务，但创建大量子任务前需要计划确认；默认最多展示两层层级。

### 3.3 人工交接

当动作无法或不应自动完成时，Agent 创建 HumanAction：

- 清楚说明用户要做什么、原因、所需资料和截止时间
- 用户完成后可上传结果或标记完成，Run 从 waiting_input 恢复
- 不把“我无法完成”作为最终答案后直接结束整个目标

## 4. Connector 平台

### 4.1 统一接口

```python
class ConnectorAdapter(Protocol):
    provider: str

    async def start_auth(self, context: AuthContext) -> AuthStart: ...
    async def complete_auth(self, callback: AuthCallback) -> Connection: ...
    async def refresh(self, connection: Connection) -> ConnectionStatus: ...
    async def list_capabilities(self, connection: Connection) -> list[ToolSpec]: ...
    async def subscribe(self, trigger: TriggerSpec) -> Subscription: ...
    async def revoke(self, connection: Connection) -> None: ...
```

Connector 提供认证、能力和事件订阅；具体动作仍注册为标准 Tool，继续经过 Phase 6 PolicyEngine。

### 4.2 OAuth 与同步

- OAuth 2.1 + PKCE + state；请求最小 scope
- access/refresh token 进入 SecretStore
- 连接状态：active / needs_reauth / rate_limited / revoked / error
- 增量同步使用 provider cursor，不能每次全量抓取
- Webhook 验签、重放保护、去重和过期恢复
- Provider rate limit 转为可重试错误，并按连接独立限速

### 4.3 数据位置

每个连接器明确说明：

- 哪些内容进入 yuanai 云端
- 哪些只在调用时临时读取
- 是否进入长期记忆/知识库
- 保留多长时间
- 是否可以改为桌面本地执行

## 5. 连接器交付波次

### Wave 1：通用基础

- 通用 Web 搜索/网页
- 本地与云端文件
- Google Calendar / Microsoft Calendar
- Gmail / Microsoft Outlook：首版读取、分类和草稿；发送需审批
- Google Drive / OneDrive
- GitHub：仓库读取、Issue/PR 草稿；写操作需审批

### Wave 2：知识与协作

- Notion
- Slack / Microsoft Teams / 飞书：搜索和草稿，发送需审批
- Todoist / Microsoft To Do / Apple Reminders（后者走桌面节点）
- Google Docs/Sheets/Slides
- Dropbox / Box

### Wave 3：专业场景

- Linear / Jira
- HubSpot 或通用 CRM adapter
- Shopify / 电商只读经营数据
- 社交平台内容草稿与排期；发布始终审批
- 财务软件只读报表；转账、付款和税务申报不自动执行

连接器的选择由用户需求、API 稳定性、安全能力和维护成本共同决定，不以数量作为阶段完成指标。

## 6. 首批场景模板

场景模板是经过评测的 Workspace + Skill + Connector + Automation 组合，不是硬编码页面。

### 6.1 日常生活

**每日安排**

- 汇总日历、任务、天气和用户临时输入
- 发现冲突并给出调整建议
- 创建/移动事件必须审批

**旅行规划**

- 研究目的地、交通、住宿和行程
- 结合用户偏好与已有日历
- 输出可编辑行程、预算表和准备清单
- 预订和付款由用户手动完成

**购物研究**

- 明确需求和约束，比较来源、价格和评价
- 标注广告/联盟来源和抓取时间
- 生成候选清单；不自动下单

**家庭事务**

- 共享清单、提醒、资料归档和事件协调
- 家庭空间需要独立成员权限，不共享个人私密记忆

### 6.2 学习研究

**学习计划**

- 依据目标、截止时间和可用时段拆解计划
- 根据完成情况滚动调整，不因一次延误重排全部内容

**资料研究**

- 搜索、去重、可信度分类、笔记和带引用报告
- 区分原文事实、模型推断和用户观点

**复习助理**

- 从知识库生成问题、闪卡和阶段测验
- 学习记忆与个人隐私记忆分开保存

### 6.3 普通工作

**会议准备与跟进**

- 汇总日历、历史邮件、项目资料和参与者背景
- 会前生成 briefing；会后生成纪要、任务和邮件草稿
- 对外发送与创建共享任务需要审批

**邮件助理**

- 聚类、优先级、摘要、待办提取和草稿
- 默认不自动发送，不把邮件正文写入长期记忆
- 用户可为固定联系人和固定模板授予受限自动回复

**文档与数据工作**

- 从多来源生成报告、表格、演示和图表
- 所有数字保留计算来源和生成代码/公式

### 6.4 创作者

- 选题雷达 -> 资料研究 -> 大纲 -> 草稿 -> 校对 -> 素材 -> 排期
- 维护品牌语气、禁用表达和事实来源
- 发布前进行事实、版权、链接和平台格式检查
- 公开发布默认审批

### 6.5 开发者

- Issue 理解 -> 代码库检索 -> 方案 -> 沙箱修改 -> 测试 -> PR 草稿
- 不在未授权仓库写入，不直接 push 受保护分支
- CI、Review 和部署状态进入任务时间线

### 6.6 OPC / 自由职业

- 潜在客户研究和个性化沟通草稿
- 客户会议、需求、报价、交付和回访跟踪
- 内容生产与多渠道排期
- 每周经营简报：客户、交付、现金流资料、内容和风险
- 合同、发票和财务数据仅做整理/提醒，签署和付款人工完成

## 7. 计划与预览

涉及三个以上外部动作或任一高风险动作时，先生成 Plan Preview：

- 目标和成功标准
- 将访问的数据与连接
- 预计步骤、时间和成本
- 会产生的外部变化
- 哪些步骤需要审批/人工
- 失败时如何回滚或停止

用户可编辑目标、禁止某连接、调整预算或直接批准计划。只读短任务可跳过计划页直接执行。

## 8. 主动助理

### 8.1 信号来源

- 日历临近和冲突
- 任务截止与依赖阻塞
- 用户授权的邮件/消息事件
- 自动化结果异常
- 长期目标进度偏离

### 8.2 打扰预算

- 通知按紧急、重要、建议分级
- 同类建议去重和冷却
- 每个空间可设置静默时间、每日上限和允许渠道
- 没有明确行动价值的“你可能想……”不发送
- 用户连续忽略/拒绝会调整该类信号权重

### 8.3 解释

每条主动建议必须说明触发原因、使用了哪些数据、建议动作和关闭该类建议的方法。

## 9. 多端体验

### Web/Desktop

- 完整 Workspace、任务、计划、Artifact 和连接管理
- Desktop 提供本机执行、拖拽文件和人工接管浏览器

### Mobile

- 今天页、快速输入、语音、审批、提醒、任务状态和结果查看
- 不强求移动端承载复杂 Workspace 编辑器
- 支持拍照/扫码作为任务输入，但敏感图片需要明确保留策略

### 通知

- Run 完成、失败、等待审批、等待人工和重要主动建议
- 点击通知精确进入对应 Run/Approval/Task
- 多设备已处理状态同步，避免重复审批

## 10. 质量与评测

### 10.1 场景指标

- Task completion rate
- 用户修改计划比例
- 草稿采用率与修改量
- 外部动作审批通过/拒绝率
- 人工完成时间节省
- 主动建议点击、完成、忽略和关闭率
- 连接器错误率与重新授权率

### 10.2 Golden Journeys

每类场景至少 5 条端到端任务，使用固定测试账号和沙箱：

- 日历冲突处理
- 旅行研究与行程 Artifact
- 邮件整理、会议 briefing 和跟进草稿
- 多文件数据报告
- GitHub Issue 到 PR 草稿
- OPC 周报

评测同时检查正确性、引用、权限、审批、成本和耗时。

### 10.3 连接器契约测试

- OAuth、刷新、撤销、scope 降级
- 增量同步、Webhook 去重和 rate limit
- 外部对象幂等创建/更新
- Provider 字段变化和部分失败
- 测试租户之间连接和事件隔离

---

## 11. 验收标准

- [ ] 新用户无需理解工具协议即可从场景模板完成第一个真实任务
- [ ] 生活、学习、普通工作至少各有一条稳定 Golden Journey
- [ ] Gmail/Outlook、Calendar、Drive 和 GitHub 至少完成一组生产级连接器
- [ ] 邮件发送、外部消息、共享日历修改和 PR 写操作均正确审批
- [ ] 生活、学习和工作空间的记忆、连接和知识不会错误串用
- [ ] “今天”页只展示可行动信息，主动建议受打扰预算约束
- [ ] Mobile 可完成审批、人工交接、语音输入和结果查看
- [ ] 连接器断连、限流或 scope 变化时任务可恢复并清楚提示
- [ ] 用户可查看每个任务访问了哪些数据、产生了哪些变化

**进入 Phase 10 的许可证**：至少 6 条跨连接器 Golden Journey 连续运行达到成功率、安全和成本阈值，并完成真实用户灰度反馈闭环。
